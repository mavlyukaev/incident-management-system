# ИС регистрации и обработки IT-инцидентов

Учебный проект по дисциплине «Технологии проектирования и сопровождения информационных систем».
Объект — техническая поддержка сайта условной телекоммуникационной компании
(SIM, eSIM и перенос номера). Система предназначена для внутренней работы инженеров;
обращения клиентов поступают из внешней системы контакт-центра через REST API в JSON.
Реальные сведения работодателя и клиентские данные не используются.

## Текущий этап

ЛР № 4: формирование среды разработки. Подготовлен только технический каркас FastAPI
с `GET /health`. Регистрация инцидентов, SLA, статусы, связи и интеграция с КЦ
пока не реализованы. ИИ-компоненты отсутствуют. Схема БД и подключение к БД не созданы.

Утверждены Python 3.13, FastAPI, PostgreSQL, PlantUML и pgAdmin ERD,
VS Code, Git и GitHub. PostgreSQL планируется устанавливать нативно в Windows
после отдельного согласования. Технология пользовательского интерфейса пока не выбрана.

## Установка и запуск в Windows

Требуются установленный Python 3.13 и Git. В PowerShell из каталога проекта:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Если окружение `.venv` уже создано, повторять первую команду не требуется.
Активация окружения и изменение политики выполнения PowerShell не нужны.
В VS Code выберите интерпретатор `.venv\Scripts\python.exe` через команду
`Python: Select Interpreter` при установленном расширении Python.

Сервер запускается только на локальном интерфейсе. Остановка — `Ctrl+C`.
Проверка из второго окна PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

Ожидается HTTP 200 и JSON `{"status":"ok"}`. Endpoint подтверждает доступность процесса
приложения; он не проверяет PostgreSQL и не подтверждает готовность бизнес-функций.
Документация API: <http://127.0.0.1:8000/docs>, схема: <http://127.0.0.1:8000/openapi.json>.

`requirements.txt` фиксирует прямые и транзитивные зависимости проверенного окружения.
Прямые зависимости текущего каркаса — `fastapi` и `uvicorn` без дополнительных наборов.
После установки проверить согласованность пакетов:

```powershell
.\.venv\Scripts\python.exe -m pip check
```

## Структура

```text
app/
  __init__.py
  main.py
docs/
  business-rules.md
requirements.txt
.gitignore
README.md
```

Локальное окружение `.venv/` исключено из Git. Пароли, токены, локальные `.env`,
закрытые ключи и резервные копии БД не должны попадать в репозиторий.
На текущем этапе приложению не нужны секреты или переменные окружения.

## Основания проектирования

Актуальные правила и ссылки на исходные учебные материалы приведены в
[документе бизнес-правил](docs/business-rules.md). Основные итоговые отчёты ЛР № 1–3
имеют суффикс `_ТПИС`; более поздние явно утверждённые поправки ЛР № 3 имеют
приоритет над устаревшими формулировками ТЗ и инструкций. Сданные отчёты и ТЗ
не изменяются. Исходные материалы хранятся в родительском учебном пространстве,
в этот репозиторий они не копируются.

Репозиторий: <https://github.com/mavlyukaev/incident-management-system>.
